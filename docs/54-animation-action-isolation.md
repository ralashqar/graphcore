# Isolated animation action prompts

Policy: `animation-action-prompt-1.1.0`. Worker: `game-animation-studio-2.2.3`.

## Problem and fix

The saved polite bow and friendly wave had distinct provider requests, clip IDs and GLB hashes. Independent playback showed a raised-arm gesture in the bow asset. Its prompt contained the complete previous wave action. This is evidence of an action-fidelity failure; prompt contamination is a plausible cause, not a proven account of the model's reasoning.

The deterministic flexible prompt compiler now sends only the selected node's action, shared performance style and its own labelled starting/ending posture descriptions. It never copies a neighboring node's action text, for either one-shot or looping motions. Cyclic and root-mode guidance remains intact. Existing explicit saved-source dependencies still supply a full-body ending-pose constraint through flexibleRecipe; runtime transitions alone do not fabricate such constraints.

The planner is instructed to write physical posture boundaries rather than narrate predecessor actions. The semantic critic receives the actual compiled prompts alongside the graph and checks action ambiguity and incompatible posture boundaries using exact graph evidence. This reuses the existing bounded critic and repair flow; there is no new model call.

Preflight fingerprints and worker checkpoint inputs include the new prompt policy. Existing reports require a fresh readiness review for new generation. Existing accepted assets, frozen jobs and review decisions are preserved. The full request remains subject to the 1500-character limit; it is never silently truncated.

## Verification and rollout

15 prompt/preflight tests passed, including wave-to-bow action isolation, exclusion of neighbor edits, loop root modes, prompt-length checks and rejection of reports from the old policy. Full regression: 726 passed, 8 skipped. TypeScript, Deno worker checks, production build, dev startup and browser console checks passed. animation-studio and all three graphcore-game machines were deployed successfully. A live worker compiler probe returned the new policy and a bow-only prompt despite an incoming wave transition, without inference.

Deploy animation-studio and the isolated graphcore-game worker together. No schema migration, native Runpod image update or GPU request is needed. The world worker and preview renderer do not execute this compiler.

## Limits

This is a prompt correctness fix, not an automatic visual action evaluator. Existing technical clip checks still do not prove that generated motion matches its requested action. The old bow asset is not repaired or regenerated by this change. Real-motion quality under the new prompt remains untested; no inference is submitted by this rollout.

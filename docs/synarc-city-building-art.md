# City building artwork

## Implementation

The merchant's saved business name, description, category, brand colour, logo and hero image drive a constrained sprite generation. The optional text field describes the business; it cannot supply a model URL, render prompt, camera, size, policy or reference URL. Existing website import and media upload supply the business information and owned references.

`city-building-art` authenticates through the same SynArc auth boundary, verifies ownership, and enqueues the new `city_building_sprite` kind in **visual_generation_jobs**. The existing character-sheet Fly visual worker performs Fal submission, request-ID recovery, webhook/polling and heartbeat/completion. There is no additional worker, provider account, campus generation loop or experimental spending ledger.

Models are explicitly allowlisted: `fal-ai/nano-banana-2/edit` and `openai/gpt-image-2/edit`. “GPT Image Edit 2.5” is not an implemented model identifier. Both adapters request one square PNG; Nano uses its documented 1K/aspect-ratio options and disables web search. The selected model is frozen on the job, independent of worker default-model settings.

## Fixed image contract

Policy `city-building-sprite-1.0.0` pins SHA-256 hashes of the checked-in tile reference and studio style reference. The worker supplies these first, followed by signed owned logo/hero references. The server prompt explicitly distinguishes camera/layout, style, and brand identity. Assets ship with the existing Fly image.

Generation uses opaque magenta outside the footprint. CPU Sharp processing:

1. Bounds downloads to 20 MiB, decoding to 16 million pixels; rejects animated, non-square and undersized output.
2. Normalizes to 512px and flood-fills only edge-connected chroma/transparent pixels. Enclosed pink branding survives.
3. Rejects clipped images, unusable background, missing ground edges, asymmetric/isometrically incorrect slopes and poor edge fits.
4. Fits the visible lower diamond, applies **uniform** scale/translation to the fixed tile anchors, and resamples with premultiplied alpha.
5. Saves a transparent RGBA PNG and geometry evidence. Failed geometry remains an unpublished failed candidate.

This validates silhouette/footprint alignment, not brand truth or artistic quality. A model can still produce a poor building; the merchant preview and publication review remain necessary. No promise of perfect generative output or verified internal building perspective is made. BiRefNet is not required for this version, avoiding a second paid generation and an unpredictable segmentation step.

Original generated bytes are retained privately for CPU recovery. Completed candidates use `city-media/<owner>/<job>.png`; only signed previews are returned. Signed URLs are refreshed on reads. The City renderer consumes already-transparent pixels, uses the same camera orientation and footprint at either plot size, preserves alpha-aware selection and existing movement animations, and excludes the old building/billboard for that property. The editor shows the resulting image rather than a rotatable 3D model.

## Endpoint and accounting

POST actions (all require bearer authentication and `businessId`):

- `read`: enabled state, configured model credit prices and eight recent owned jobs with short-lived previews.
- `generate`: `jobId` (idempotency UUID), saved `version`, `model` (`nano` or `gpt`), optional `direction` (1,200 chars).
- `retry`: `jobId`; only recovers an existing provider request or saved raw image, without a new charge or submission.
- `apply`: `jobId`, saved `version`; adds validated art to that exact business draft. Does not publish.

The service-only start RPC atomically checks ownership, saved snapshot, active-job exclusion, twelve-per-day bound and existing SynArc generation credits. Idempotent requests return the same job without charging twice. Prices must be explicitly configured as positive integers (maximum 1,000) before that model is enabled. City Value and Stripe geography are untouched.

Failures before provider submission refund through the existing credit ledger exactly once. Once submission starts, the generation charge is retained, including rejected geometry and uncertain acknowledgements. An uncertain submission without a request ID fails closed and requires reconciliation; recovery cannot blindly resubmit. A deliberate new generation is a separately charged request. No automatic paid repair loop exists.

City jobs have nullable project/draft IDs plus a business FK and a context constraint. All existing non-City jobs still require both project and draft. A restrictive RLS policy prevents client roles from reading or authoring City visual jobs through generic endpoints; service-only commands expose bounded owner views. Generated art cannot be injected through normal profile save: that action can preserve or remove the already-applied path, while changing it requires the validated candidate action.

## Rollout

Implemented locally; **not migrated, deployed, activated or tested with fresh paid inference**. The earlier City release constraint excludes production activation/new provider spending, and no designated staging target was supplied. Existing production credentials are not evidence of staging authorization.

1. Apply `20260921132230_city_building_art.sql` to the designated staging database. The enum addition must commit before the new kind is inserted.
2. Deploy `city-building-art`, `city-api`, `city-command`, `city-reconcile` and `city-stripe-webhook` (the latter four bundle changed `city.ts`). Deploy the existing world worker with `fly.world-generation.toml`; build ID `2026-09-21-city-art-1`. The static Sharp import is cached in the existing Docker build. No game, animation, preview or other worker deployment is needed.
3. Deploy frontend. Set appropriate `CITY_ART_NANO_CREDITS` and `CITY_ART_GPT_CREDITS` on Edge. Reuse existing `FAL_KEY`, storage, auth and worker wake configuration.
4. Enable `CITY_BUILDING_ART_ENABLED=true` on both Edge and world worker only for the approved rollout. Zero/missing model price disables that model. Default remains false.
5. Verify a real authenticated logo-reference generation on staging, credit debit/recovery, rejection UX, apply/review/publish, and alignment in the actual City before broad activation. Existing prototypes and mock API tests do not substitute for that acceptance.

Provider schema references: [Nano Banana 2 edit](https://fal.ai/models/fal-ai/nano-banana-2/edit/api), [GPT Image 2 edit](https://fal.ai/models/openai/gpt-image-2/edit/api). Long-running generation remains on Fly rather than depending on [Edge background execution limits](https://supabase.com/docs/guides/functions/background-tasks).

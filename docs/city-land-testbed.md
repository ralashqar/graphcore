# City land and construction test bed

## Trying it

Open `/city?demo=1` using the procedural preset renderer. The test bed is enabled by default there; `cityBuild=0` disables it for comparisons. Other city render modes and live city data are unaffected.

Drive to the edge of the populated city, exit with E, and approach a fenced vacant plot's street-facing entrance. The prompt is available within two metres while grounded, with a clear approach. E or the touch button inspects it. Purchase is **simulated USD $5**, with no real payment. Cancel returns to the street. Purchased land is fixed in position, independently of City Value/ranking.

Construction uses the existing v3 recipes and shared renderer. Choose a preset from the bottom carousel; switch to Grounds, Nature, Style or Branding for a compact side panel. Drag roof/side handles to resize within recipe limits, or use +/- controls. Orbit and zoom on the canvas. Save & Finish commits the visible building and returns to walking. Exit saves an unfinished draft. Revisiting restores that draft while the last finished building remains the public local-world presentation outside the editor. Undo/redo covers the current session; one dimensional drag produces one history entry.

### Sculpt mode

Building now has Presets and Sculpt tabs in the local test bed. Supported rectangular, L-shaped, courtyard, stepped and round presets convert into a version-1 sculpt recipe; specialised twin towers remain preset-only. Draw joined rectangles, circles or ellipses, or cut a courtyard. Select a shape and drag to move or resize it; buttons provide precise size changes. The top-down button points the existing orbit camera at the plot and leaves orbit/zoom available. Each floor inherits the nearest lower authored outline until edited, and can be linked again. Roofs in Sculpt are flat, parapet or planted; converting a pitched preset chooses flat.

The recipe stores only authored shapes on detached floors in the existing local `LandDraft`, alongside the unchanged v3 preset recipe. Switching tabs preserves both until a new preset is chosen; only a deliberate new preset clears the prior sculpt outline. Undo/redo, autosave, draft/finished separation and local revision checks apply to sculpt edits. Older saved worlds have no sculpt field and continue opening in Presets. Sculpt is not part of public business profiles or live City endpoints.

The sculpt worker unions and subtracts plan shapes, triangulates roof openings, emits connected wall runs and inset window/door openings, and rejects detached floors with unsupported overhangs. Shape counts and buildable coordinates are bounded. The last valid building remains visible while a new result is prepared; stale worker results are ignored. Plot grounds, fences and the construction camera stay mounted. A single worker is shared among sculpt properties. No Blender, CSG mesh boolean or server call runs during editing.

The street-facing entry receives a sign using the saved building name and an approach strip joining the plot entrance. Seeded plants avoid that route. Repeated windows and connected wall surfaces are emitted into five material meshes per sculpt building rather than separate draws per bay. The same component displays the active draft and the finished design after construction. No public profile or endpoint schema changed.

Sculpt verification (September 2026): 15 combined land/sculpt domain tests pass, including all 32 preset compositions at minimum/maximum plot dimensions, union/courtyard topology, inherited and detached floors, overhang rejection and finished/draft persistence. `scripts/city-sculpt-browser.mjs` passes native WebGPU and WebGL for purchase, conversion, floor edit, courtyard drag, tab switching, finish and stored recipe checks. The pre-existing `scripts/city-land-browser.mjs` passes its full preset/purchase regression. TypeScript and the production build pass; a fresh Vite dev server served `/city?demo=1` without server errors. Existing chunk-size and landing-image build warnings remain.

Sequential 72-property driving checks on the same Edge/WebGPU desktop setup measured p95 18.2 ms with the land test bed off and 18.3 ms with it on; controller p95 was 0.2 ms in both. Draw calls were 49 versus 57 and triangles 168,969 versus 220,675. CPU-only resolution of 400 default sculpt recipes took 676 ms total, with a 2.83 ms p95 per recipe; this does not measure GPU upload or full-scene rendering. The separate 400-property driving fixture rendered without page errors after making billboard atlas anisotropy compatible with WebGPU, but recorded p95 500.6 ms over 57 frames. That large-scene result remains a performance problem and does not meet the frame-time target. Physical-mobile verification is also outstanding. Evidence: `output/city-drive-sculpt-baseline-72.json`, `output/city-drive-sculpt-72.json` and `output/city-drive-sculpt-400.json`.

The driving HUD exposes a separately confirmed Reset test world action. This removes local purchases/designs, not any real business data.

## Data and integration

`cityLand.ts` defines version-1 plot/world records and the asynchronous LandRepository contract. The local simulator persists under `city-land-v1-{plotSize}-{capacity}` using browser storage. The initial occupied demo snapshot is frozen with the vacant allocation. Both 24-unit plots and whole 48-unit estates use their own layout coordinates; roads, the centre and launch plaza are excluded. All available plots have a permanent collider independent of rendering.

Purchase checks availability/revision, assigns the local test owner and writes a receipt immediately. Same-receipt retries are idempotent. Draft/finish commands require ownership and the expected revision. Commands serialize within a repository and use browser Web Locks across tabs when available. The local test identity/storage are not a security boundary. A future server adapter must derive identity, price and ownership on the server and verify payment using its provider webhook before purchase completion. No existing GBP City Value contracts are repurposed.

Autosave debounces edits, serializes in-flight saves and does not clear dirty state for newer edits. Storage failures retain the editor/draft and expose Retry. Revision conflicts offer explicitly confirmed reloading of the saved version. Leaving with unsaved data requests the browser's normal unload warning. Reload resumes safe exploration, not mid-staging/celebration.

The existing exploration actors and camera remain mounted. Inspection, purchasing, celebration and construction exclusively own input while active. The character follows a short collision-checked path to a safe street marker. Near-car and near-plot interactions use reachable distance, with car winning ties. Reduced motion skips staging travel and confetti. Construction editing changes recipes, never arbitrary mesh vertices. Dimensions are clamped to 8–18 recipe units (higher blueprint minimums still apply) and at most eight floors; estates scale the same recipes consistently. Dragging previews bounds only and commits geometry on release. Construction retains the last prepared recipe while the worker prepares its replacement, avoiding blank buildings between edits; ordinary city rendering keeps its existing preparation policy.

## Assets and performance

`public/assets/city/nature/source.json` records source URL/version, archive hash and selected GLB hashes. The four original GLBs and CC0 licence are retained. Runtime preparation normalizes ground origins and relative heights and uses matte bark/leaf colours with zero metalness. Geometry/materials are cached and repeated plants/fences/signs are instanced. Failed downloads retain procedural greenery. Nature placement is seeded; building bounds and the entrance route suppress overlapping plants without changing the seed. The optional grass/paving choices reuse existing texture presets.

## Responsive construction presets

Interactive preparation is keyed by recipe content, so autosave/object refreshes do not restart identical work. New recipes prepare in a worker; the old building stays mounted with a loading indicator and usable carousel. Only the latest requested recipe is accepted. A prepared replacement scales the entire building out/in through one plot-centred transform; reduced motion switches immediately. Handles and Finish wait for the visible result. Worker failures retain the previous building and expose Retry, rather than running the expensive geometry/AO fallback on the main thread. Ordinary city loading preserves its existing fallback.

CPU preparation is asynchronous; Three.js mesh updates and GPU uploads still occur on the rendering thread. This is not a claim of zero GPU upload cost. The browser regression includes delayed preparation, responsive tab changes, retained old geometry, injected worker failure and successful retry.

The responsive-construction browser regression passed on native WebGPU and WebGL with reduced motion, including injected preparation failure/retry and delayed worker responsiveness. The WebGL setup needed a longer walking timeout while the production build was running. Nine land-domain tests and TypeScript passed; no new browser page errors were reported.

Production build passed after the responsive-preview changes. Existing landing-image and chunk-size warnings remain. The development server remains available at `http://127.0.0.1:5188/city?demo=1`.

## Seamless dimension editing

Only explicit preset selection requests a scale transition. Floors, width, depth, palettes, branding and grounds replace prepared geometry in place. Initial entry also displays at full scale. The orbit target is captured per plot entry and zoom limits no longer depend on the changing building height, preserving framing during edits.

Interactive preparation retains its completed worker for subsequent jobs, releasing it on unmount or cancelling unfinished work when superseded. Surrounding vacant plots have a revision-keyed instance set separate from the active plot's landscaping; editing and autosaving the active plot no longer regenerate their fence/sign/plant instance buffers. The city stays visible.

The browser regression asserts idle/full-size dimension updates and unchanged camera position/target across a floor change, followed by preset loading/retry, undo/redo, direct handles and save/reload. The first run passed; a measured floor update took 1,181 ms including 400 ms of intentional settling during a concurrent production build. This is not an isolated performance benchmark or a claim that all geometry uploads are instantaneous.

Resize handles remain visible and editable during preparation/autosave; the existing revision-aware save queue preserves newer edits. Only finishing waits for preparation. Final surrounding-instance browser verification passed with unchanged framing, no dimension animation, preset switching, failure/retry and purchase/save/reload.

## Vertical construction transitions

Preset transitions now render stationary plot surfaces/perimeter enclosures separately from the animated building. Building geometry and attached signs scale on Y only around the plot surface datum; X/Z remain exactly one. The old building collapses completely before the new building rises, without overshoot. Ground-slot planters/bollards are marked as stationary generated geometry; rooftop planting remains attached to the building. Imported paving and ground prop assemblies use the same separation. Grounding stays on the stationary layer. Other city/customiser renderers retain their combined default layer.

Dimension changes still replace geometry without animation or camera changes. No recipe schema, saved profile, public API or deployment changes are introduced by the generated-part layer hint.

Vertical-transition verification: browser assertions passed for ordered outgoing/incoming phases, collapse to the footprint and fixed X/Z scales, plus unchanged dimension-edit framing and the purchase/save/reload regression. TypeScript and nine land-domain tests passed.

## Architectural brushes for Sculpt

Sculpt now supports constrained door, canopy, entrance-pillar, façade-trim, planter and low-light brushes. Paint on exposed walls or clear ground; trim and ground groups can be dragged to set their span. Placement uses a camera ray independent of the rendered building mesh so roof and ground meshes do not steal brush input. A placement is one undoable edit. The right panel also lists authored details and explains inactive ones.

The local Sculpt recipe moves to version 2 when the first detail is placed. It stores attachment intent and keeps version-1 shapes readable. Doors snap into a street-facing façade bay, move the existing sign and approach route, and cause windows to refill the other bays. Canopies and paired pillars bind to the primary entrance. Ground details avoid the shell, entry path and plot edge; seeded vegetation also clears their footprint. Full-run trim can meet at a corner with a small joint. Shape edits retain attachment choices and mark those that no longer fit inactive, so restoring a suitable shape restores the detail.

The shared Sculpt worker resolves both the active preview and finished city building. Decorative Quaternius doors, planters and bollards load on demand for the stone/metal styles, with procedural fallbacks in light mode or when the pack fails. Curved Sculpt buildings retain their automatic entrance; relocating a door with the brush currently requires a sufficiently long straight street-facing wall. No public business profile, payment or server contract changes.

Verification: 20 combined land/Sculpt domain tests pass, including off-centre door reflow, dependent canopy relocation, fit/invalidation, ground overlap and version-1 geometry equivalence. The purchase-to-finish brush flow passed in both WebGPU and WebGL, placing a door, canopy, pillars and planter, then exercising undo/redo and saved version-2 persistence. ## Reactive architecture graph

The local Sculpt editor upgrades a recipe to version 3 when its owner edits it. Existing version-1 and version-2 saved buildings keep their prior renderer until then. Version 3 stores source-face anchors for doors and façade trim, plus a semantic full-wall trim choice. Resizing a source face moves its door, repacks its windows, extends full-wall trim, and updates the dependent canopy, pillars, entrance path and cleared vegetation. Removing that source face preserves the authored choice as inactive. Restoring it restores the detail.

The worker derives a typed dependency graph in this order: floor outlines, exposed wall runs, façade bays, roof edges, attached assemblies and grounds. It still performs a complete worker rebuild per committed edit; the graph establishes stable identities and rules rather than claiming incremental mesh updates. The Move face tool drags an exposed rectangular edge while holding its opposite edge fixed; curved outlines retain whole-shape Resize. Shape dragging shows lightweight bounds and commits one undo action on release. The editor also offers one-action storefront glazing, continuous trim and entrance porch, plus a fitted pitched gable on a single rectangular top floor. An incompatible top shape retains the pitched selection while displaying a flat roof and an explanation. The graph is internal; there is no player-facing node editor or Blender execution.

Current verification: 26 combined land/Sculpt tests pass, including fixed-opposite-edge face moves, face-anchor resizing, dependent porch movement, trim extension, dependency propagation, graph bay changes, all convertible presets and pitched-roof face normals. The purchase-to-finish flow passes in WebGPU and WebGL with version-3 persistence and the quick adaptations. TypeScript, the production build and fresh dev startup pass. `scripts/city-sculpt-graph-benchmark.ts` resolved the same 400 mixed presets after warmup: legacy 234 ms total / 1.87 ms p95 per building, graph 258 ms total / 2.48 ms p95, with 718,290 versus 717,862 emitted triangles. All 8,518 outer-wall segments in that fixture received a source anchor. This is worker-side CPU resolution, not a rendered frame benchmark; the earlier 72/400-property driving results predate version 3. Physical-mobile and touch validation remain open.

## Live Sculpt drag preview

Dragging a shape or exposed rectangular face now sends temporary intent to a plot-scoped preview channel, without editing the saved draft or creating undo entries. A background worker resolves the same walls, façade bays, roof, doors and attachments used by finished buildings. Requests begin at most once per 100 ms and retain only the latest pending shape while a request runs. Obsolete results are ignored; invalid candidates leave the last valid building visible and show a red outline with a fit explanation. Releasing the pointer validates once and commits one edit; cancellation restores the saved building. Grounds, fencing and the construction camera do not rebuild for transient drags.

The browser regression waits for a frame containing the preview before releasing the pointer and verifies that local persistence still contains the original shape at that moment. On the desktop test setup, one sampled drag took 4 ms in the worker and 75 ms to a visible WebGPU frame; WebGL was 4 ms and 14 ms. These are single interaction samples, not frame-time percentiles or a 400-property performance result. Both browser backends, 27 combined focused tests, TypeScript and the production build passed. The existing 400-property streaming hitch and physical-mobile validation remain open.

## Original SynArc architectural tile kit

Blender 5.2.2 and the connected Blender MCP generated an original, editable low-poly kit. The source `.blend`, reproducible builder, measured manifest and 93-part GLB are in `assets/city/synarc-kit/v1`, `scripts/build-city-synarc-kit.py` and `public/city/synarc-kit/v1`. Three families—warm brick, painted townhouse and modern office—share 2 m by 3 m by 0.30 m wall bays with 1 m and 0.5 m plain fillers. Openings own their wall material and replace a whole bay. The kit also has closed corners, continuous base/roof-edge pieces, doors, canopies, balconies, rails, buttresses and small attachments. No Quaternius geometry or textures enter this pack.

The optional version-1 `synarcKit` recipe on version-3 building designs stores style, window/door choices, attachments and authored paint intent. One exposed-wall resolver places measured parts for both the business designer and in-world Sculpt editor. The business designer offers bounded per-bay opening and accent choices; Sculpt offers a wall brush. Rounded and specialised bridge/tower designs keep their existing façade. Older recipes remain unchanged. The GLB loads lazily, falls back to procedural walls until ready, and repeated meshes are merged per part/material then instanced. Invalid paint selections remain authored and report why they are inactive.

The construction browser flow verifies purchase, style/window selection, persistence and visible kit loading on WebGPU and WebGL2. A separate mock-backed business editor flow verifies per-bay painting, an accent and saved draft choices. The asset checker validates 93 parts, 8,864 source triangles and the GLB hash; 34 focused V3/Sculpt/kit tests and the Deno schema check pass. A 72/400-property kit-specific rendered frame benchmark, touch-device validation and physical-mobile profiling remain open. Keep this local test-bed feature off production until those checks and the matching endpoint/frontend/world-worker staging rollout are planned.

## Rectangle Sculpt union repair

Rectangle primitives now use explicitly closed rings and a robust polygon union/difference resolver. The prior clipping path could return missing area or diagonal edges even for axis-aligned overlapping rectangles, producing triangular holes in roofs and deleting parts of the footprint. Additions and cuts are grouped per operation. Rectangle drag placement also keeps the exact snapped endpoints instead of re-snapping the midpoint, so drawn edges and later moves stay on the intended grid. Regression tests check two reproduced failures, 3,000 seeded rectangle layouts against an independent exact-area calculation, triangulated roof area and a rectangle joined to an ellipse. The purchase-to-Sculpt browser flow now draws a rectangle and passed after the change; TypeScript and production build also passed. The 400-property CPU resolver check measured 416/465 ms total and 3.13/4.24 ms p95 for legacy/graph modes on one isolated run; an immediate repeat measured 424/525 ms and 3.40/4.82 ms. These are not frame-time measurements and differ from the earlier pre-kit baseline, so a controlled before/after performance comparison remains open.
